# Статусы и источники

Статус: подтверждено  
Дата: 2026-09-11

## Использованные источники

1. Описание бизнес-модели владельцем процесса в разговоре «Архитектура учета металлоприемки».
2. Обсуждение целевой ledger-архитектуры в том же разговоре.
3. Книга `Мотобелки.xlsx`, SHA-256 `b9b75313f763b7df9a903ccf1d23f1ed006a762c22dd9debcec78d7583dc1d32`.
4. Согласованный план запуска: GitHub, VPS, Telegram bot, домен и Markdown-база знаний.

Исходная книга содержит PIN и другие операционные сведения, поэтому она намеренно не добавлена в Git. В документации используются только структура листов, обезличенные поля и формулы.

## Подтверждённые факты

- Мерчант направляет деньги на карты металлосдатчиков по предоставленному набору карт.
- После оплаты мерчант присылает XLSX-реестр с суммами по картам.
- Деньги снимают сборщики или операционисты, передают главному администратору и затем возвращают мерчанту.
- Мерчант рассчитывается наличными с реальными металлосдатчиками.
- «Металлист» получает комиссию за финансовое сопровождение.
- Есть непостоянные расходы, личные расходы и инъекции главного администратора.
- Операционисты отчитываются через Telegram.
- Карты имеют лимиты входящих операций и снятия.
- На дату запуска будет существующая кредиторская задолженность без полной истории.
- Нужен ledger с изолированными и аудируемыми событиями.

## Принятые технические решения

- один приватный monorepo;
- modular monolith вместо микросервисов;
- Go API, PostgreSQL, React admin и Telegram bot;
- S3-совместимое хранение исходных файлов;
- double-entry ledger;
- Markdown-документация в Git;
- отдельные source, business и ledger слои.

## Предложения, ожидающие бизнес-подтверждения

- точный план счетов;
- моменты признания комиссии и погашения задолженности;
- конкретные статусы документов;
- точное распределение прав;
- правила частичных операций и аллокации;
- структура отчётов и KPI;
- политика хранения персональных данных.
