# Секреты и чувствительные данные

Статус: принято
Дата: 2026-09-11

## Запрещено хранить в Git

- Telegram bot token;
- SSH private keys;
- пароли сервера и БД;
- S3 access keys;
- cookie/session secrets;
- PIN карт;
- production dumps;
- неанонимизированные реестры и Telegram exports;
- полные карточные данные без отдельного утверждённого режима.

## Разрешённые references

- имя переменной, например `TELEGRAM_BOT_TOKEN`;
- bot username;
- secret storage path без значения;
- public key;
- checksum исходного файла;
- обезличенные fixtures.

## Правила

- отдельные secrets для local, staging и production;
- минимальные права;
- rotation после раскрытия или смены участника;
- секрет не выводится в log/error;
- config endpoint не возвращает секреты;
- токен, ранее опубликованный в переписке, должен быть перевыпущен до production;
- PIN из `Физ!C:C` книги «Мотобелки» не мигрирует в систему.

## Карточные данные

Владелец процесса разрешил хранить полный PAN для рабочих реестров. Главный администратор вводит его при создании карты либо дозаполняет ранее заведённую карту. Основная БД хранит `card_id`, банк, маску и последние четыре цифры; полный PAN сохраняется отдельно как AES-256-GCM файл по `card_id` в закрытом каталоге `PAN_VAULT_DIR`. Ключ из `PAN_KEY_FILE` находится вне Git и БД. Оператору и главному администратору доступен экспорт полного номера только в XLSX выбранного запроса; действие записывается в аудит без PAN. Обычный экран и API справочника возвращают только маску. PIN и CVV не принимаются и не хранятся.

Согласно [разъяснению PCI SSC](https://www.pcisecuritystandards.org/faqs/1222/), отсутствие CVV не исключает применимость требований к хранению PAN: сохранённый PAN должен быть нечитаемым, а связанные данные защищены. Программное шифрование здесь не означает завершённую оценку PCI DSS или законодательства о персональных данных; оценка области применения, процессов доступа, ключей, резервных копий и сроков хранения остаётся открытой. Образец CSV содержит только маскированные номера; отсутствующий PAN нельзя восстанавливать догадкой.

ФИО и телефон платёжного контакта сохраняются в справочнике и неизменяемом снимке строки запроса. Реальные данные допускаются владельцем процесса, но их правовое основание, срок хранения, удаление/обезличивание и дополнительная защита требуют отдельного решения. Новые исходные файлы ответных реестров шифруются тем же ключом; исторические исходные файлы не переписываются автоматически. `PAN_KEY_FILE` и `PAN_VAULT_DIR` должны резервироваться отдельно от БД с раздельным доступом; потеря ключа делает номера и новые исходные файлы невосстановимыми.
