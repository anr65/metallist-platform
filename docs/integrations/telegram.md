# Telegram

Статус: проект; инфраструктура частично готова
Дата: 2026-09-11

Бот: `@metallistcash_bot`. Токен хранится вне Git и не документируется.

## Принцип

Telegram update сохраняется как источник, а не как инструкция обойти финансовые правила. Parser создаёт draft business event или наблюдение остатка. Для первого запуска **любая денежная операция** из Telegram требует отдельного явного подтверждения главного администратора после показа карты/источника и точной суммы, которая будет списана. До подтверждения ledger posting не возникает. Наблюдение остатка само по себе не является денежной операцией и не меняет ledger; его расхождение требует отдельного разрешающего события.

## Предлагаемые команды

```text
/withdraw <card-ref> <amount-rub> <observed-balance-rub>
/expense <source-ref> <amount-rub> <category> <comment>
/handover <recipient> <amount-rub>
/repay <merchant> <amount-rub>
/balance <card-ref>
```

В первом запуске обязательны ввод снятия с фактическим остатком карты после снятия и ввод расходов. Команды/формы должны сохранять сумму снятия отдельно от наблюдаемого остатка, а расход — с категорией и фактическим источником списания. Для операций, которые сами вносятся главным администратором, его явное подтверждение в интерфейсе всё равно необходимо; второе лицо не требуется. Сообщение или повторная доставка update не считается подтверждением.

Синтаксис окончательно утверждается в TG-001. Денежные единицы должны быть одинаковыми и явными; вариант `100` как тысяча рублей в целевой команде нежелателен.

## Idempotency

- уникальный `(bot_id, update_id)`;
- оригинальный chat/message ID;
- повторная доставка возвращает предыдущий результат;
- edit сообщения создаёт новую версию источника и не меняет posted event;
- delete сообщения не удаляет учётную историю.

## Доступ

- Telegram user ID связывается с активным внутренним пользователем;
- username не используется как идентификатор;
- разрешённые команды зависят от роли;
- неизвестный пользователь не получает финансовые данные;
- групповой чат и личный чат имеют разные политики раскрытия.

## Ошибки

Бот отвечает понятной причиной и не публикует частично разобранную операцию. В сообщениях нельзя показывать полный номер карты, PIN, токен или чужие финансовые детали.
