# Миграция 008: рабочие запросы карт

Статус: подготовлено; production не изменён.
Дата: 2026-09-21.

Владелец процесса разрешил хранить полные номера карт при заведении карты и использовать их в запросе мерчанту. CVV и PIN не принимаются. Номер шифруется AES-256-GCM в отдельном каталоге; ключ лежит вне Git и БД. Обычный справочник показывает только маску и признак наличия номера. XLSX создаётся при авторизованном скачивании, аудируется по SHA-256 и не сохраняется открытым файлом. Новые исходные файлы ответных реестров также шифруются на диске. Старые документы остаются неизменными.

`schema/008_production_card_requests.sql` после версии 007 разрешает `NULL` в прежних полях пути/хеша XLSX и учебных номера/имени строки. Старые данные не удаляются. Новые запросы хранят выбранный `card_id` и снимок контакта, без суммы и без полного номера.

Перед применением: точная проверка БД и версии 7, свежий закрытый `pg_dump -Fc`, проверенное восстановление копии, резервная копия каталога исходных документов. Проверить миграцию и инварианты ledger на восстановленной копии. В production применить миграцию одной транзакцией с `ON_ERROR_STOP=1`, сверить количество объектов и дисбаланс. Затем установить ключ `PAN_KEY_FILE` и закрытый каталог `PAN_VAULT_DIR`, резервное копирование обоих и только потом запустить совместимый релиз.

Rollback приложения после появления новых запросов невозможен на старый код, рассчитанный на обязательный сохранённый XLSX. Использовать исправленный новый релиз. Не удалять схему и не терять зашифрованные номера. Потеря ключа делает сохранённые номера и новые исходные файлы невосстановимыми.
