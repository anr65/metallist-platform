# Миграция 002: запросы карт к оплате

Статус: план для отдельной демонстрационной БД. Дата: 2026-09-14.

## Цель и границы

Цель — только `metallist_demo` на VPS `metallcash.work`. Разрешение владельца распространяется на отдельную демонстрационную БД с синтетическими данными; другие БД и настоящие реквизиты вне этой операции. Прикладная роль получает на новых таблицах только `SELECT, INSERT`. Миграция добавляет две таблицы, необязательную ссылку из `registries`, индексы и запись версии 2. Существующие денежные строки и postings не меняются.

## До выполнения

1. Установить точные `current_database()`, `current_user`, сервер и `max(schema_migrations.version)=1`. Сверить список таблиц и текущие суммы ledger; остановиться при расхождении.
2. Создать свежий `pg_dump -Fc` с закрытыми правами, проверить размер, список содержимого и восстановить файл в выделенную одноразовую БД с именем `_test`. Проверить схему, счётчики документов и баланс ledger в восстановленной копии. Записать путь и время проверенного backup в журнал выпуска.
3. Применить `schema/002_payment_requests.sql` к точной цели одной транзакцией с остановкой при ошибке. Проверить версию 2, ограничения, доступ прикладной роли и неизменность прежних итогов ledger.
4. Развернуть приложение по точному SHA и проверить HTTPS, вход, создание планового запроса, экспорт и связанный импорт на синтетических данных.

## Восстановление

Новый код до миграции не включать. При ошибке в транзакции схема откатывается автоматически. Если приложение после миграции неработоспособно, вернуть предыдущий SHA приложения; добавленная схема совместима со старым кодом. Обратное удаление таблиц и ссылки на демонстрационной БД не делать: это уничтожит созданные запросы. Если нужен полный возврат состояния, сначала остановить запись, согласовать потерю новых демо-записей и восстановить проверенную резервную копию отдельно по инструкции восстановления.

Для production требуется новый план с защищённым хранилищем реквизитов и отдельное разрешение; эту миграцию нельзя считать разрешением на настоящие PAN или ФИО.
