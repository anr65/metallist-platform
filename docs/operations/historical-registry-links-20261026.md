## Исполнение

Проверены host `deploy@167.233.162.67`, сервис `metallist-platform.service`, `/opt/metallist-platform/current`, application release `3008e5355c9b0be76860b2ae15867858959bea51`, рабочая БД `metallist_demo`, схема 29 и активный chief-актор. [Скрипт](../../scripts/link-historical-registries-20261026.sql) содержит точные ID 62 согласованных пар и ожидаемые версии, суммы, даты, число строк, SHA-256 источников и digest состава строк. Карты сопоставляются по внутренним ID, не по последним цифрам. ФИО/телефоны, номера карт и исходные реестры в скрипт не включены.

Скрипт выполняется одной SERIALIZABLE-транзакцией с advisory/table locks и таймаутами. До записи повторно проверяются отсутствие связи, статус, мерчант, доступность и версия запроса, полный состав, отсутствие ошибок и совпадение сохранённых ФИО ручного источника с картой запроса. Совокупность оплат каждого запроса должна покрывать его полностью без пересечений. Изменены только `registries.payment_request_id` и версия этих 62 документов; версия повышена на 1 для защиты от устаревших действий. Статусы, суммы, даты, карты, комиссии, исходные строки, снимки запросов и финансовая история сохранены.

На каждый документ добавлен audit event `registry_request_link`, channel `owner_chat`, actor — действующий главный администратор, ключ `owner:20261026:historical-registry-links:except-5-129`. Аудит содержит прежнюю и новую связь, версии, основание и явное разрешение владельца, без контактных и карточных данных. Повтор проверяет согласованность 62 связей с аудитом и ничего не записывает.

## Возврат ошибочной связи

Автоматический откат после COMMIT не выполняется. Если владелец отменит конкретную привязку, подготовить отдельную аудируемую metadata-коррекцию: проверить текущую связь и версию, исключить зависимые изменения состава, явно согласовать целевую связь, повысить версию и сохранить обратное событие аудита. Исходный аудит не удалять. БД целиком из backup не восстанавливать и ledger не изменять ради исправления связи.
