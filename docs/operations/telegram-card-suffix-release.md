# Telegram: выбор карты по последним 4 или 6 цифрам

Дата: 15.10.2026. Статус: выпущено на production.

При совпадении четырёх цифр бот явно просит повторить весь пакет с шестью цифрами нужной карты. Оба формата принимаются в снятиях и карточных расходах, включая смешанный пакет и ввод после выбора команды из меню. Правила выбора и отказа — в [интеграции Telegram](../integrations/telegram.md#идентификация-и-доступ).

Изменены только разрешение карточного реквизита и подсказки. Схема 25, роли, внутренний `card_id`, суммы, проводки, подтверждение, сторно и ключи идемпотентности сохраняются. Миграций и исправления исторических данных нет. Для шести цифр требуется чтение существующего защищённого номера; отсутствие доступа к любому кандидату блокирует пакет, не разрешая выбрать другую карту догадкой. Полный PAN не попадает в ответы или ошибки.

Проверки: полный `go test -race ./... -count=1`, `go vet ./...`, `go build` и `git diff --check` успешны. Одноразовый PostgreSQL 17 создан с нуля в `/tmp/metallist-suffix-qa.8XDw3K`: 127.0.0.1:55447, база `metallist_platform_test`, пользователь `metallist_qa`, `APP_ENV=testing`; до схемы подтверждены effective identity, data directory и отсутствие таблиц. Применены схемы 001–025. Новые сценарии покрывают обе формы хранения PAN, коллизии 4/6 цифр, недоступный номер, неверную длину, неактивные карты, смешанный диалог, расход, выбор правильных карт в postings, повтор подтверждения и отсутствие частичного черновика. Прежние финансовые, ролевые и sensitive-input проверки проходят. UI не менялся.

Перед выпуском: подтвердить host `deploy@167.233.162.67`, service `metallist-platform.service`, current `/opt/metallist-platform/current`; создать защищённую копию и проверить restore. Выпускать точную вершину `origin/main` через `scripts/deploy-production.sh`. Проверить SHA current, systemd, local/public health и журнал запуска. Финансовые smoke-команды за пользователей не выполнять.

Откат: штатное переключение current на прежний release и перезапуск сервиса. Схема и финансовая история не меняются; старый код снова принимает только четыре цифры. Уже созданные черновики содержат внутренний `card_id` и совместимы со старым кодом.

История отклонённых сообщений: `telegram_updates` сохраняет только метаданные, аудит — причину и update ID; текст не прошедшего парсинг пакета отсутствует. Успешно разобранные сообщения доступны в `drafts.payload.telegram_raw`. Близкое время следующей операции само по себе не доказывает повтор исходного пакета. Сверка не публикует пропущенные операции автоматически; источник, карта и фактическое событие должны быть установлены отдельно.
