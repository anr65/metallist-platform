# Справочник банков НСПК для новых карт

Статус: рабочая интеграция. Дата: 2026-09-21.

Источник — [официальный перечень участников СБП НСПК](https://sbp.nspk.ru/participants). Публичный сайт загружает перечень из `https://sbp.nspk.ru/rest/v1/banks/list`; отдельный контракт этого HTTP-интерфейса не опубликован, поэтому обновление проверяет формат, число записей и полноту страниц. На 21.09.2026 источник возвращал 233 организации. Перечень участников СБП сам по себе не доказывает, что выбранный банк выпустил конкретную карту: операционист сверяет банк по реквизитам, система не выводит его из BIN.

Миграция `schema/010_nspk_banks.sql` добавляет к `banks` источник, внешний UUID, признак выбора для новой карты и время последней сверки. Существующие карты и их ссылки на банки не меняются. Четыре исторические записи `BIN220015`, `BIN220038`, `DEMO1`, `DEMO2` остаются в базе для чтения старых карт, но не предлагаются при создании новой. Обновление загружает полный перечень до начала транзакции, затем атомарно добавляет/обновляет банки и скрывает исчезнувших участников из выбора. Карты исчезнувшего участника сохраняются. Ошибка источника или сокращение списка более чем на 5 % оставляет прежний каталог и делает сервис обновления ошибочным.

Перед production-применением проверить точные хост и БД `metallist_demo`, версию схемы 9, число банков/карт и нулевой дисбаланс проводок. Создать закрытый backup базы, PAN-каталога, ключа и конфигурации, проверить контрольные суммы и восстановить базу в отдельную временную БД. На копии применить 010 одной транзакцией и сверить прежние количества и права прикладной роли. Затем применить 010 к production и развернуть совместимый коммит из `main`. Запустить `platform sync-nspk-banks` в окружении production и проверить число активных записей НСПК в `banks`, число карт и `/health`. Только после успешной первой загрузки включить `metallist-nspk-bank-sync.timer`: каждое воскресенье 01:00 UTC. Контролировать состояние `metallist-nspk-bank-sync.service` и его журнал при неудаче.

Проверка перед выпуском 21.09.2026: набор `/var/backups/metallist-platform-protected/20260921T132409Z` прошёл проверку SHA-256 и каталога дампа; база восстановлена в `metallist_010_restore_test`. До миграции: версия 9, четыре банка, 114 карт, две проводки. После 010: версия 10, те же количества, четыре исторических банка исключены из нового выбора, права на точечное обновление каталога у прикладной роли есть, дисбаланс проводок 0.

Миграция добавочная и сохраняет старый бинарник работоспособным. При неудачном релизе вернуть предыдущий бинарник, не удаляя новые столбцы и банки. После создания карты, связанной с банком НСПК, откат на старый код не теряет эту связь: `bank_id` остаётся обычным UUID. Копию базы восстанавливать совместно с защищённым PAN-хранилищем и ключом.
