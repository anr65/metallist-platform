# Два подтверждения Telegram-перевода — выпуск 05.10.2026

Статус: **выпущено на production 05.10.2026 в 16:35 МСК**; release gate GO, выпуск явно запрошен владельцем.

## Поведение

`/transfer` работает только между сборщиками. Первое подтверждение отправителем в рабочей группе оставляет `draft` и резервирует всю сумму. Получатель запускает личный чат через `/start` и принимает всю сумму либо отклоняет перевод. Главный администратор может принять вместо получателя в кабинете; автор подтверждения сохраняется явно. Второе подтверждение атомарно освобождает резерв и публикует одну сбалансированную запись. Ожидание бессрочное; отказ/отмена освобождают резерв без проводок. Другие списания и сторно защищают активные резервы.

Запросы и итоги сохраняются в очереди; неудачная доставка повторяется после перезапуска. `/pending` в личном чате повторно доставляет ожидающие запросы. Передача главному администратору в эту команду не входит.

## Исправление блокировки справочника — 05.10.2026

При подтверждении нового черновика Ферб → Тони на 400 000 ₽ production вернул `permission denied for table custodians`: `FOR SHARE OF u,c` требует права UPDATE на хотя бы один столбец обеих таблиц. Production-role имеет SELECT на справочник хранителей и UPDATE отдельных столбцов users, поэтому блокировка custodians недопустима. Общая ветка ошибки ошибочно сообщала о смене привязки, хотя оба участника оставались активными и корректно связанными.

Исправление блокирует только строки users (`FOR SHARE OF u`). Статус/тип хранителя читаются в существующей serializable-транзакции; права БД не расширяются. Отсутствие подходящего участника (`sql.ErrNoRows`) отличается от ошибок БД, последние получают безопасное сообщение `DATABASE_ERROR`. Схема, суммы, резервы и posted-история не меняются; существующий черновик можно подтвердить повторным нажатием после выпуска исправления, без отмены и создания дубля.

Добавлена проверка полного первого/второго подтверждения под отдельной ограниченной ролью на disposable QA-БД: SELECT custodians без UPDATE, SELECT users и UPDATE только telegram_id/custodian_id, доступ к финансовым таблицам. Проверены отсутствие postings до второго подтверждения, одна конечная entry и снятие резерва; отдельный REVOKE SELECT проверяет корректную классификацию ошибки БД. GO: полный набор тестов с race detector, vet, Go build и diff-check прошёл перед исправляющим application-релизом на isolated QA-БД metallist_platform_test (127.0.0.1:55623). Миграций и ручного проведения production-перевода нет.
