Применять `schema/011_edit_card_requests.sql` после версии 010 одной транзакцией. До запуска проверить точную production-базу, создать свежую закрытую копию БД и каталога PAN, проверить контрольные суммы и восстановить копию в отдельную базу. Сначала применить миграцию к восстановленной копии и проверить, что прежние запросы, строки, карты и проводки не изменились. Затем применить к production и выпустить совместимый код. Миграция только добавляет поля и права роли приложения на изменение запросов и строк; старый код продолжает читать прежние данные.

Проверка после выпуска: версия схемы 11, число ранее созданных запросов и строк не уменьшилось, суммы проводок по дебету и кредиту равны, оператор может изменить несвязанный запрос, связанный ответный реестр блокирует изменение, удалённый запрос скрыт из списка и не экспортируется, аудит содержит исполнителя. При неуспехе приложения вернуть предыдущий release, оставив совместимую добавочную схему. Для восстановления данных использовать проверенную закрытую копию; не удалять строки финансовой истории.

Исправление 2026-09-21: оператор сообщил об ошибке «карта или контакт недоступны» при сохранении существующего запроса. Причина — SQL пытался установить `FOR SHARE` на строку `payment_contacts`, тогда как прикладная роль имеет там только `SELECT`. Блокировка контакта убрана, проверка существования и активности контакта сохранена. На восстановленной копии под реальными правами прикладной роли проверены чтение строки, блокировка карты, удаление и вставка строки, повышение версии запроса; транзакция откатана, копия удалена. Добавлен регрессионный тест с ограниченной ролью.
