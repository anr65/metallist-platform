# Миграция 003: Telegram-сборщики

Статус: применена к `metallist_demo`
Дата: 2026-09-17

## Назначение

`schema/003_telegram_collectors.sql` добавляет роль `collector`, уникальную связь пользователя с хранителем наличных, защищённое сохранение Telegram update и краткоживущий выбор команды из меню. Бот принимает операции только из одной группы, явно заданной `TELEGRAM_ALLOWED_CHAT_ID`; автор каждой команды по-прежнему определяется по личному Telegram user ID. Существующие `users`, `drafts`, проводки и балансы не переписываются. Новые поля nullable; ранее развёрнутая версия приложения может работать после добавления схемы до переключения кода. Публикация кнопкой использует прежний immutable ledger и ключи идемпотентности.

## Проверенная тестовая цель

Локальная disposable PostgreSQL `metallist_platform_test` на `127.0.0.1:55434` с ролью `metallist_qa`, `APP_ENV=testing`, отдельными учётными данными и явным `TEST_DATABASE_URL=DATABASE_URL`. Проверен полный цикл: свежая копия `metallist_demo` восстановлена только в эту тестовую БД с `--no-owner --no-acl`; до миграции совпали `2` пользователя, `1` черновик, `3` реестра, `10` journal entries, `26` postings, нулевой общий дисбаланс и версия `2`. Миграция 003 выполнена в одной транзакции с `ON_ERROR_STOP=1`; после неё версия `3`, счётчики и дисбаланс не изменились. Тесты Telegram и полной системы запускаются только там.

## Выполнение в демо

Перед изменением владелец явно разрешил последовательность 003 → 004 для `metallist_demo`. Непосредственно перед ней подтверждены `APP_ENV=demo`, `current_database()=metallist_demo`, версия 2, 10 journal entries, 26 postings и нулевой дисбаланс ledger. Создана закрытая копия `/var/backups/metallist-platform/metallist_demo_before_003_004_20260917T113759Z.dump` (135 326 байт, права `0600`), её каталог успешно прочитан `pg_restore -l`; предшествующая копия того же состояния фактически восстановлена в локальную одноразовую `_test` БД.

003, требуемые права, 004 и её права применены одной транзакцией через выделенную owner-конфигурацию. После миграции версия 4, 10 journal entries, 26 postings и нулевой дисбаланс. Прикладная роль получила точечные права на Telegram-связь, диалоги и подтверждение существующих документов, но не получила `UPDATE` к `journal_entries`, `postings` или `audit_events`.

После миграции развёрнут точный commit `c9cccffd9b1c3b71b1ed1300fe7ca3f1676eb185`. Бот остаётся выключен до появления перевыпущенного токена по пути `TELEGRAM_BOT_TOKEN_FILE`; секрет webhook уже создан в закрытой конфигурации. После появления токена `/start` выдаст ID группы, который нужно записать как `TELEGRAM_ALLOWED_CHAT_ID` и перезапустить сервис. В BotFather отключается Group Privacy, а в группе боту выдаётся право удаления сообщений для очистки случайно отправленного полного номера карты. Старый опубликованный токен не использовать.

Откат кода к прежнему SHA возможен без удаления новых nullable-колонок и таблицы диалогов. Если после миграции уже проведены Telegram-операции, их не удалять и не откатывать схему; исправления денег — только сторно и новое событие. Полное восстановление из backup допустимо только как отдельная согласованная операция с оценкой событий после копии.
