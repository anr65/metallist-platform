## Откат и диагностика

Вернуть предыдущий application release штатным переключением current и перезапуском, схему 029 и историю оставить. Активный пошаговый handover перед новым вводом отменить через `/cancel`; старый код не понимает ожидание суммы этой команды. Pending-представление/ошибки старый worker не обрабатывает: предпочтителен roll-forward. Не перепроводить документы ради восстановления Telegram.

Диагностика: `SELECT draft_id,chat_id,last_error,next_attempt_at FROM telegram_operation_messages WHERE last_error<>'';` и `SELECT operation,code,field,row_number,resolved,last_error FROM telegram_input_errors;`. Не выводить токен, сырой вход или production-env. Telegram ограничивает удаление старых сообщений; ошибка очистки не меняет ledger. Сбой между первоначальным sendMessage и COMMIT может повторить доставку, финансовый повтор исключён. Исторические карточки без сохранённого ID не очищаются массово; авторизованный callback привязывает старую карточку.
