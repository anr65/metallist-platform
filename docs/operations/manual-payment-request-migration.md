# Миграция 006: ручной состав запроса карт

Статус: применено к `metallist_demo` 2026-09-21; приложение разворачивается отдельно
Дата: 2026-09-21

`schema/006_manual_payment_requests.sql` после версии 005 расширяет допустимые значения `payment_requests.mode` значением `manual`. Существующие запросы, строки, XLSX и суммы не меняются. Приложение с ручным созданием запросов разворачивается только после этой миграции. Прежняя версия приложения продолжает читать записи; удалять новое значение при откате приложения нельзя.

Перед применением проверить точную цель, текущую версию 5 и резервную копию. На выделенной одноразовой тестовой БД применить SQL одной транзакцией, проверить версию 6, сохранность старых записей и создание запроса с `mode='manual'`. Замена ограничения берёт кратковременную блокировку таблицы `payment_requests`; выполнять в согласованное окно и проверить отсутствие долгих транзакций. После миграции сверить число запросов, строк, `journal_entries` и `postings` с показателями до неё. Для demo и production нужны отдельные разрешение и процедура резервного копирования, описанная в [миграции 005](payment-contact-migration.md).

При возврате старой версии приложения схему 006 сохраняют. Удаление строк или обратное сужение ограничения не является штатным откатом.
