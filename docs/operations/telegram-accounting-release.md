# Личный учетный бот sysadmin — выпуск 27.10.2026

Статус: подготовлен, production-результат будет дополнен после выкладки.

## Состав и gates

[Задача TG-ACCOUNTING-01](../to-be/telegram-accounting-control.md): полный web-доступ sysadmin, привязка Telegram без хранителя, личные уведомления после возврата/передачи, запросы реестров с защищенным подтверждением, балансы мерчантов/касс/всех карт. Событие очереди фиксируется в финансовой транзакции; доставка не проводит деньги. Для возврата позиция мерчанта после операции сохраняется в metadata очереди, поэтому поздняя доставка не подменяет ее текущим балансом. Последующие сторно отмечаются в уведомлении.

Схема 032 после 031 аддитивна: две новые таблицы, индекс и grants. Новых денежных правил, backfill ledger и массовой рассылки истории нет. Lock timeout 5s; пустые новые таблицы не переписывают существующие данные. Старые получатели переводов и личные команды Тони сохраняются.

Локальная disposable PostgreSQL 17: 127.0.0.1:55917, metallist_platform_test, metallist_qa, отдельный mktemp data directory (путь в /tmp/metallist-accounting-test-path). До схемы проверены effective DB/role/address/port и отсутствие public tables. Полный go test -race ./... -count=1, go vet, build, UI production build, 8 UI-тестов и diff check обязательны. Новые тесты покрывают финансовый результат, повторы и гонку web/bot, измененный тариф/строки, отзыв и смену привязки, очередь/rollback/сбой/повтор, все балансы, частичный факт и пагинацию, а также ограниченные production-style SQL-права. Браузерная проверка локального sysadmin включает доступ к обзору/реестрам, форме подтверждения, диагностике очереди и форме Telegram без обязательной кассы.

## Порядок выпуска

1. Проверить host deploy@167.233.162.67, service metallist-platform.service, current /opt/metallist-platform/current, схему 31 и исходный release.
2. Свежий закрытый backup scripts/backup-production.sh. Проверить SHA256SUMS, восстановить dump в явно выделенную metallist_accounting_restore_20261027 и распаковать files в закрытый временный каталог. Не читать секреты в tool output.
3. На восстановленной копии проверить идентичность цели и контрольные хеши финансовых таблиц; применить 032 одной транзакцией, сверить прежние хеши, grants и representative queries от metallist_demo_app без финансовых публикаций. Удалить временную копию после успешной проверки.
4. Зафиксировать точный проверенный commit в origin/main. Кратко остановить приложение, создать свежий backup, сохранить fingerprints и применить ровно проверенную 032 к production. Сверить fingerprints; схема 32.
5. Штатный scripts/deploy-production.sh с точным SHA. Проверить systemd, current, local/public health, startup log и SHA-256 UI-ресурсов. Не проводить финансовые операции для smoke.
6. Telegram ID владельца связать только с явно выбранной им учетной записью; роль sysadmin и привязку записать в одной транзакции с аудитом. Собственного хранителя не назначать по предположению. Никаких самопроизвольных /start за пользователя: личный чат подключает владелец.

## Откат и восстановление

Исходный application release: ed0fe48eea32f487b7d52e324026bfb7cd870a17. Вернуть current на него атомарной заменой symlink, перезапустить сервис и проверить health. Оставить схему 32, очередь, previews, документы и postings. Старый бинарник не обрабатывает новые callback ar:/ab:; вернуть новый код для их продолжения. Финансовые результаты не отменяются откатом приложения, исправления — только штатным сторно. Если sysadmin назначен бывшему chief/operator, старый код вернет прежние ограничения sysadmin: отдельно откатить изменение роли к записанному исходному значению с аудитом либо выполнить roll-forward. Backup не восстанавливать поверх последующих финансовых действий.

Остаточные ограничения: Telegram не дает exactly-once доставки; после сбоя возможно повторное сообщение. Кнопки в копиях у других администраторов остаются видимыми, но сервер отклоняет повторное проведение. Для доставки необходим /start каждого sysadmin. Offsite backup остается прежней эксплуатационной задачей.
