# Реквизиты входа в адресной строке

Статус: исправление подготовлено к выпуску 2026-09-21.

Кабинет выполняет вход через `POST /login` с JSON в теле запроса, но навигация ошибочно сохраняла произвольный query string, полученный при открытии сайта. Из-за этого ссылка с параметрами `login` и `password` оставалась в адресной строке. Эти параметры не использовались сервером для входа. В production Caddy и приложение уже отправляли `Referrer-Policy: no-referrer`; в конфигурации Caddy не включён access log.

Исправление: сервер перенаправляет любой запрос главной страницы с query string на `/` без параметров, не отражая их в ответе; API отклоняет реквизиты входа в query. Интерфейс при запуске удаляет query из истории и больше не переносит его при навигации. Тесты проверяют отсутствие значений в ответе и `Location`, запрет query для API и сохранение текущей вкладки при очистке адреса. Существующие пароли пользователей не меняются автоматически, чтобы не лишить их доступа без безопасного канала передачи новых реквизитов; затронутый пароль требуется сменить через «Настройки входа» или административный сброс.
