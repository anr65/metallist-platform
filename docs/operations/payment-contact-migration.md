# Миграция 005: ФИО и телефоны для запросов карт

Статус: подготовлено, demo не изменяется без отдельного разрешения
Дата: 2026-09-19

## Изменение

`schema/005_payment_contacts.sql` после версии 004 создаёт справочник `payment_contacts` и добавляет к `payment_request_rows` ссылку на контакт и неизменяемый снимок ФИО/телефона. Новые поля nullable ради совместимости с ранее созданными запросами: старым строкам не приписывается выдуманный телефон. Новая версия приложения требует заполненный активный контакт для каждой новой строки. Миграция не меняет `journal_entries`, `postings`, суммы запросов или сохранённые XLSX.

`deploy/demo-grants-005.sql` выдаёт прикладной роли минимальные права на новый справочник и поля строк. `deploy/demo-seed-005.sql` добавляет в `metallist_demo` только три синтетические записи с заведомо учебными телефонами. Реальные ФИО и телефоны в demo запрещены.

## Проверка на одноразовой БД

Цель должна иметь `APP_ENV=testing`, локальный PostgreSQL, отдельную роль и имя БД с окончанием `_test`/`_testing`. Перед применением подтвердить `max(schema_migrations.version)=4`, создать одну старую строку запроса без контакта и записать контрольные количества ledger. Применить 005 одной транзакцией с `ON_ERROR_STOP=1`.

После применения требуется доказать:

- версия схемы равна 5;
- старая строка сохранена, а три новых поля остаются `NULL`;
- справочник принимает нормализованный телефон и не принимает неполную пару снимка;
- новый запрос без контакта отклоняется приложением;
- новый запрос хранит `contact_id`, `contact_name`, `contact_phone` для каждой строки;
- выгруженный XLSX содержит ФИО и телефон, контрольная сумма совпадает;
- количества `journal_entries`/`postings` и общий дисбаланс ledger не изменились.

## Применение к demo

До операции нужны явное разрешение владельца именно на миграцию 005 в `metallist_demo` и свежая восстанавливаемая резервная копия. Проверить точную БД, роль, сервер, версию 4 и нулевой ledger-дисбаланс. Создать закрытый `pg_dump -Fc`, проверить `pg_restore -l`, восстановить его в отдельную `_test` БД и выполнить там 005. Только после успешной проверки выполнить в одной транзакции `schema/005_payment_contacts.sql`, `deploy/demo-grants-005.sql` и `deploy/demo-seed-005.sql`, затем развернуть совместимый commit.

Откат выполняется возвратом приложения на предыдущую версию без удаления новых таблицы и колонок. Удаление схемы не входит в штатный rollback, чтобы не потерять сохранённые контакты и снимки.
