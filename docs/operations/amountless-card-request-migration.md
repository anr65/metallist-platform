# Миграция 007: запрос карт без суммы

Дата: 2026-09-21. Цель: `metallist_demo` на `metallcash.work`, ветка `demo-v1`.

`schema/007_amountless_card_requests.sql` после версии 006 добавляет режим `cards`, разрешает `NULL` в двух полях суммы запроса и одном поле суммы строки. Ограничение требует пустые суммы в режиме `cards` и сохраняет заполненные суммы у старых режимов. Существующие строки, проводки и XLSX не переписываются. Новое приложение принимает только режим `cards` и создаёт XLSX без колонки суммы. Сумма поступления берётся из ответного реестра.

## Порядок применения

1. Проверить имя БД `metallist_demo`, текущую версию схемы 6, количество запросов и строк, количество `journal_entries` и `postings`, отсутствие несбалансированных проводок.
2. Сделать свежий закрытый `pg_dump -Fc`, проверить каталог через `pg_restore -l`, восстановить в отдельную временную БД из `template0` и сверить контрольные количества.
3. Применить миграцию к восстановленной БД одной транзакцией с `ON_ERROR_STOP=1`; проверить версию 7 и ограничения.
4. Повторить контроль исходной БД, применить миграцию одной транзакцией, сверить количества и ledger.
5. Развернуть точный SHA из `demo-v1` скриптом `scripts/deploy-demo.sh`; проверить сервис, `/health`, текущий SHA и собранные ресурсы.

Откат приложения возможен переключением на предыдущий релиз только если новый код ещё не создал запросов режима `cards`: предыдущий код не рассчитан на `NULL` в суммах. После создания таких запросов нужен исправленный совместимый релиз; откат самой схемы и удаление данных не входят в штатный сценарий.
