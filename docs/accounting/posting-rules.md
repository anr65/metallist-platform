# Правила проводок

Статус: проект, требует подтверждения BIZ-001 — BIZ-010  
Дата: 2026-09-11

Примеры описывают предлагаемую механику. Они не утверждают ещё не согласованный момент признания.

## Пополнение карты мерчантом

При подтверждённом факте, выбранном как момент возникновения долга:

```text
Дт 1100 Деньги на картах                  amount, card_id
Кт 2100 Долг перед мерчантом              amount, merchant_id
```

## Снятие

```text
Дт 1200 Наличные у ответственного         amount, custodian_id
Кт 1100 Деньги на карте                   amount, card_id
```

Долг перед мерчантом не меняется: деньги только сменили место.

## Передача главному администратору

```text
Дт 1210 Наличные у главного администратора amount
Кт 1200 Наличные у отправителя             amount
```

Если нужна двухэтапная передача, между ними используется `1220 Наличные в пути`.

## Возврат мерчанту без удержания комиссии

```text
Дт 2100 Долг перед мерчантом              amount, merchant_id
Кт 1210 Наличные у администратора         amount
```

Точка публикации зависит от BIZ-002.

## Комиссия сверху

При начислении отдельной дебиторки:

```text
Дт 1300 Дебиторка мерчанта по комиссии    fee, merchant_id
Кт 4100 Комиссионная выручка              fee, merchant_id
```

Поступление комиссии:

```text
Дт денежный счёт                          fee
Кт 1300 Дебиторка мерчанта по комиссии    fee
```

## Комиссия удержана из возврата

Вариант без предварительного начисления при долге `principal` и фактической выдаче `principal-fee`:

```text
Дт 2100 Долг перед мерчантом              principal
Кт 1210 Наличные у администратора         principal-fee
Кт 4100 Комиссионная выручка              fee
```

Если комиссия начисляется раньше, используется дебиторка и отдельная операция взаимозачёта. Выбор зависит от BIZ-003/BIZ-004.

## Расход

```text
Дт счёт расхода                           amount, category_id
Кт фактическое место денег                amount, card_id/custodian_id
```

Источник денег обязателен; сообщение о расходе без него остаётся draft.

## Возвратная инъекция администратора

```text
Дт 1210 Наличные у администратора         amount
Кт 2200 Долг перед администратором        amount
```

Невозвратный вклад отражается через equity по отдельно утверждённому правилу.

## Перевод между картами

```text
Дт 1100 Деньги на карте-получателе        amount, destination_card_id
Кт 1100 Деньги на карте-источнике         amount, source_card_id
```

## Сторно

Сторно повторяет dimensions исходной записи и меняет стороны дебет/кредит. Затем при необходимости публикуется исправленная запись с новым business event и ссылкой на исходную ошибку.

## Запрещено

- проводка только по одной стороне;
- изменение posted entry;
- ручная установка баланса;
- использование наблюдаемого остатка как проводки;
- повторный post по одному idempotency key;
- отрицательная сумма вместо явного типа и направления операции.
