# Сверка

Статус: проект
Дата: 2026-09-11

## Принцип

Сверка сравнивает ledger с независимым наблюдением и не исправляет историю автоматически.

```text
расчётный остаток − фактический остаток = расхождение
```

## Объекты сверки

- карта;
- наличные отдельно у каждого сборщика или другого фактического хранителя (`custodian_id`);
- наличные у главного администратора;
- деньги в пути;
- задолженность по мерчанту;
- totals исходного реестра и применённых операций.

## Карта

`CardBalanceObservation` содержит card_id, observed_amount, observed_at, source, reporter и evidence. Разница с ledger создаёт `ReconciliationItem`.

## Касса

Модель повторяет полезную часть листа `КАССА`: opening + inflows − outflows = expected closing; факт вводится отдельно, разница расследуется.

Для сборщиков сверка выполняется по каждому `custodian_id`. Общая сумма по операционисту не заменяет индивидуальные остатки сборщиков.

## Закрытие расхождения

Допустимые результаты:

- найдено пропущенное событие и опубликована обычная операция;
- найдена ошибочная операция, выполнены reversal и replacement;
- подтверждена комиссия/расход/потеря и опубликовано соответствующее событие;
- observation признано ошибочным, создано новое наблюдение;
- расхождение остаётся открытым с владельцем и сроком.

Прямая корректировка баланса запрещена.
