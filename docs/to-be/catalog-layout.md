# Справочники в интерфейсе

Статус: реализовано.
Дата обновления: 2026-10-01.

Главная страница «Справочники» содержит компактные карточки доступных разделов. Каждая открывает отдельный список по прямой ссылке `#catalog/<раздел>`. Иерархия показывается в общей шапке через хлебные крошки. Разделы карт, контактов, банков и ответственных используют общую таблицу shadcn, 15 записей на странице и меню действий в строке. Создание и редактирование открываются в модальных окнах. Для системного администратора отдельно доступен список пользователей с модальным созданием и изменением привязки Telegram.

Главный администратор создаёт и редактирует карты, контакты, вручную заведённые банки и имена ответственных. Операционист создаёт карты и контакты и может менять их описательные поля. Банки НСПК доступны только для чтения: их данные обновляет синхронизация. Функция ответственного, статус карты и данные учёта не меняются этим редактором. Сервер проверяет роль независимо от интерфейса и пишет аудит успешного изменения.

При создании новой карты полный номер обязателен для защищённого хранения и выгрузки запроса. Дозаполнение полного номера уже существующей карты удалено из интерфейса и API. Исправление ранее сохранённого номера остаётся отдельным действием с причиной и действующими проверками отсутствия истории использования.

Все табличные списки приложения показывают по умолчанию не более 15 строк на странице. В списках запросов и операций страницы загружаются сервером; фильтры операций сохраняются при переходе между страницами.

В списке «Мерчанты» главный администратор видит столбец «Остаток задолженности» в рублях и копейках: позицию по мерчанту — кредитовый остаток счёта 2100 минус дебетовый остаток счёта 1300. Положительная сумма означает долг перед мерчантом, отрицательная — дебиторку мерчанта. Например, возврат 1 900 000 ₽ при долге 1 400 000 ₽ показывает −500 000,00 ₽. Это представление позиции: счета и отдельные статьи финансового отчёта не сворачиваются и проводки не меняются. Источник — опубликованные проводки; черновики не учитываются. Возвраты, корректировки и сторно отражаются при загрузке списка. Мерчант без проводок показывается с нулём, отключённый сохраняет позицию при включении фильтра. API каталога отдаёт точные десятичные строки `payable` (2100), `receivable` (1300) и `position` (2100 минус 1300) только главному администратору. Уточнение отображения согласовано владельцем 05.10.2026.

В справочнике карт общий поиск охватывает маску, банк, ФИО владельца, дроповода и русский статус. Отдельные фильтры по всем пяти столбцам сочетаются по AND. Для владельца доступны ФИО и заполненность («Указан» / «Не указан»), для дроповода — конкретное назначение или его отсутствие. Фильтры банка и дроповода используют внутренние ID, поэтому одноимённые записи не смешиваются. На всех ширинах отдельные фильтры находятся в диалоге «Фильтры карт». Кнопка «Фильтры» с иконкой воронки стоит справа от поиска в одной строке с промежутком 8 px. Диалог содержит карту, банк, владельца, заполненность владельца, дроповода и статус; «Применить» сохраняет условия, «Отмена», Escape и закрытие без применения оставляют прежние условия. «Сбросить» очищает поля диалога до применения, сохраняя общий поиск. Поиск, число совпадений и общий сброс доступны над таблицей. Изменение условий возвращает на первую страницу, переход по страницам и сохранение карты сохраняют условия.

В модальном редактировании карты chief/operator/sysadmin могут изменить банк через тот же поиск по названию, что при создании. Текущий исторический банк сохраняется в выборе даже при недоступности для новых назначений; для замены доступны только действующие записи. Смена банка не меняет номер карты, её ID или финансовую историю и записывается в аудит. [Контракт и ошибки](../api/commands.md#поиск-карт-и-исправление-банка--29102026).

## Серверный поиск в списках выбора — 05.11.2026

Реализовано в коде; развёртывание этим изменением не выполняется.
Общий `Select` раскрывает строку поиска над вариантами. Запросы задерживаются
на 180 мс; устаревший ответ не заменяет актуальную выдачу. Выбранное значение
сохраняется при поиске без результатов и закрытии списка. Доступны клавиатура,
обязательные поля, передача значения в форму, сброс формы, загрузка и повтор
после ошибки. Оформление соответствует `DESIGN.md`.

Аудит всех мест выбора в `ui/src`:

| Раздел / компонент | Где добавлен серверный поиск | До изменения |
|---|---|---|
| Операции: создание, включая `BalanceSelect` с подсказками балансов | Карта снятия, получатель наличных, отправитель и получатель передачи, мерчант возврата, источник денег, тип расхода | Обычный `Select` |
| Операции: фильтры | Тип операции, источник, получатель / назначение | Обычный `Select` |
| Реестры: загрузка и ручной ввод | Мерчант, запрос карт | Обычный `Select`; запросы ограничивались последними 100 |
| Реестры: ручной ввод | Карта, ФИО и телефон контакта | Локальный поиск в `ManualRegistryCardSelect` / `ManualRegistryContactSelect` |
| Реестры: список | Мерчант и статус | Обычный `Select` |
| Реестры: сверка строк | Карта и получатель из связанного запроса | Обычный `Select` |
| Тарифы | Мерчант в предварительном расчёте | Обычный `Select` |
| Запросы карт: создание / редактирование | Мерчант, карта строки | `Select` для мерчанта, локальный поиск в `CardCombobox` |
| Исправление номера карты | Карта | Локальный поиск в `CardCombobox` |
| Справочники: карта | Банк НСПК, дроповод, тип карты, пластиковая карта общего баланса, статус карты | Локальный поиск в `BankSelect`, остальные — `Select` |
| Справочники: дроповоды и ответственные | Активность дроповода, функция ответственного | Обычный `Select` |
| Справочники: пользователи | Роль при создании, ответственный при привязке Telegram | Обычный `Select` |
| Справочник карт: фильтры | Банк, заполнение владельца, дроповод, статус | Обычный `Select` |
| Запросы карт: ФИО / телефон строки | **Серверный поиск уже был** в `ContactCombobox`: `/api/payment-contacts?q=…`, страницы по 10, догрузка | Сохранён существующий серверный поиск |

Меню действий `DropdownMenu` (открыть, редактировать, подтвердить, удалить,
выйти) проверены отдельно: это команды, а не поля выбора данных; строка поиска
в них не добавляется. Нативных пользовательских `<select>` вне общего адаптера
не обнаружено.

[Контракт поиска](../api/commands.md#серверный-поиск-в-выпадающих-списках--05112026).
Источники сущностей повторно проверяют существующие права; активность,
связь запроса с мерчантом и исключение уже выбранных карт сохраняются.
Составные фильтры операций и конечные перечисления ищутся сервером по полному
набору переданных вариантов. Текущие справочники загружаются целиком;
поиск работает по всему разрешённому набору, но не переводит их загрузку на
постраничный API. Если появится такая пагинация, потребуются выдача подписей
найденных вариантов сервером и обновление адаптера поиска.
Для списка запросов добавлен `dropdown=1`: полный набор для полей выбора,
стандартная серверная пагинация таблицы не меняется.
