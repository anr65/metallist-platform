# Жизненные циклы операций

Статус: проект
Дата: 2026-09-11

## Общий lifecycle документа

```text
draft → validated → confirmed → posted
   └────────────→ rejected
```

Фактические названия могут быть уточнены, но состояния проверки и финансовой публикации должны быть разделены.

| Состояние | Смысл | Влияет на официальный баланс |
|---|---|---|
| draft | введено человеком или parser | нет |
| validated | структура и бизнес-предусловия проверены | нет |
| confirmed | уполномоченный пользователь подтвердил факт | ещё не обязательно |
| posted | journal entry опубликован | да |
| rejected | источник признан непригодным | нет |
| reversed | опубликована связанная сторнирующая запись | да, через новое событие |

## Запрещённые переходы

- `draft → posted` без проверки и подтверждения, если операция пришла из внешнего источника;
- изменение суммы или измерений после `posted`;
- удаление `posted`;
- повторный `posted` по тому же idempotency key;
- `rejected → posted` без новой валидации.

## Импорт

```text
received → parsed → validated → previewed → approved → applied
```

Повторный парсинг создаёт новую попытку с parser version и не перезаписывает исходный результат.

## Reversal

```text
original posted
      ↓
reversal posted
      ↓
replacement posted, если нужен
```

Все три записи связаны, имеют автора, время и причину.
